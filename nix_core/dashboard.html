Training data & evaluation

What went into Luna, and how it did

The archived training record lists 2,653 examples: 1,800 public conversations, 461 project examples, 18 single-turn examples written for the project, 360 multi-turn conversations, and 14 examples about Luna’s role. Within the public conversations, it lists DailyDialog (1,292), No Robots (185), UltraFeedback chosen-SFT (183), and FineTome-100k (140). The 223 examples with extra context are already included in the total. The manifest says personal chat logs weren’t used.

The saved test notes cover 18 held-out prompts. They found no exact text matches in the snapshot, though that doesn’t rule out paraphrases. In the small reported checks, Luna answered 4 of 9 single-turn prompts and 1 of 5 multi-turn prompts without added context. With context supplied by the evaluator, the scores were 6/9 and 2/5. That setup didn’t test the full Nix experience. These are historical results from a small test set, not a fresh or complete assessment.

The adapter record points to luna_targeted_v6_contextual_v2_sft.jsonl. A corrected V3 snapshot was documented later, but it wasn’t used for these weights and has no evaluation score. This page describes the existing records, not a newer training run.

Training data & evaluation

What went into Casper, and how it did

Casper V5’s recorded training used 2,941 examples and set aside 400 more for evaluation (seed 42). It was meant to shape conversation style; it was not trained to know private facts about you. V6 has records from more than one stage: an early snapshot lists 1,003 training and 250 evaluation examples, plus 53 curated examples and six preference examples. A later snapshot lists 288 training examples and 144 pairs reviewed for preference training. These are separate snapshots, not amounts to add together.

Casper V6 is a beta and is not the default. Its archived results were 7/8 on a small test that included policy guidance, 3/5 on an earlier multi-turn test, and 1/5 on the latest recorded multi-turn test. These small historical checks do not predict everyday performance or show what is available on a particular computer or hosted service.

Sources and license notes

  • DailyDialog: Li et al. (2017), ACL Anthology paper; Casper project records list CC BY-NC-SA 4.0.
  • EmpatheticDialogues: Rashkin et al. (2019), ACL Anthology paper. Project records disagree: dataset manifests list CC BY-NC-SA 4.0, while an archived source note lists CC BY-NC 4.0. Check the exact source version and terms before reuse or sharing.
  • Project-written examples and reviewed preference pairs are described in casper_puca_public_mix_v5.metadata.json and casper_v6_dataset.metadata.json. These records describe the project data, not independent verification.

Luna’s development

What each stage taught us.

The scores below come from small historical checks. They offer a glimpse of how the models handled those prompts, not a promise about every conversation.

L1–4Early base-model adapters

Luna QLoRA pilot · V2 · V3 · V4

The first versions adapted Llama 3.2 3B Base with collections of dialogue. They helped establish the project’s approach, but longer conversations still felt uneven.

What changed between early versions

Archived run notes list the `luna-qlora-pilot` (12,600 examples, 60 steps), V2 (17,354 examples, 120 steps), V3 (10,716 examples, 160 steps), and V4 (12,015 examples, 400 steps). The archived notes compare the dataset sizes and run lengths for these early experiments. They were research versions, not selectable product releases.

I1Instruct baseline

Luna Instruct V1 · conversation baseline

Switching to an instruction-tuned Llama base gave the team a more useful point of comparison. Testing also showed a weakness: without reliable context, the model could make up personal details or sound certain without enough evidence.

Identity, role, balanced, and baseline checks

In the shared small check, Instruct V1 scored 5/9 on single-turn prompts and 1/5 across multi-turn conversations. Identity V1 scored 2/9 and 0/5; Role V1 scored 3/9 and 0/5; Balanced V5 checkpoint 80 scored 1/9 and 1/5. These prompts tested Casper-style conversations, not Luna’s identity alone. Common misses included unclear follow-up questions, date mistakes, unnecessary questions, and invented details. In a separate test with written-in context, the Instruct baseline scored 7/9 and 2/5; that wasn’t a full test of Nix.

V6Recovery and targeted runs

Earlier Luna experiments · recovery and curriculum

These experiments explored clearer answers, a consistent identity, and better use of information across several turns. Some short exchanges improved, but the results were less consistent in longer conversations.

Archived checkpoints and test scores

On the same mixed Casper V6 contract, Luna Recovery V1 scored 5/9 and 4/9 single-turn, each 1/5 multi-turn. Targeted V2 scored 5/9 and 6/9 single-turn but did not sustain multi-turn performance in isolation; its higher context-assisted result (7/9 + 2/5) used evaluator-injected context. These small synthetic-context tests did not exercise the complete Nix stack. The archived curriculum and identity/role attempts are research history, not separate selectable releases.

OFFICIALOfficial · current source registry

Official Luna

This is the Luna adapter that Nix’s Transformers registry identifies as Official Luna. Its model ID is luna-v6-contextual-v1.

Test history and release-label context

In the archived comparison, Luna scored 4/9 on single-turn prompts and 1/5 on multi-turn prompts without extra context. Luna Instruct V1 scored 5/9 and 1/5. With context written by the evaluator, the scores were 6/9 and 2/5 for Luna, and 7/9 and 2/5 for Instruct V1. These small historical checks don’t settle which model is better in everyday use. “Official Luna” is the name used in Nix’s current model registry; it doesn’t tell you which model a separate hosted service is running.

The review also noted one overly broad hint about “sisters” in an older data snapshot. A corrected snapshot was documented later, but it wasn’t used for the current adapter.

PROEarly research

Luna Pro v1 · an early research candidate

Luna Pro was explored as a research candidate, but it never became a release. A small review found made-up details, repeated placeholders, and missed follow-up questions. Some dataset sources and usage terms also remained unclear.

What the review found

In an eight-prompt review, the model missed a question asking which collaborator the user meant. A separate review of its examples found an invented day-trip destination when no city had been given, along with repeated placeholders. Notes on Topical-Chat and other sources also left their usage terms unresolved.

Casper’s model history

From warmer replies to grounded conversation.

Casper has a more direct, get-to-the-point voice than Luna. The two companions use separate models.

N1–3Early conversation adapters

Qwen3.5 humanlike · pilot, V2, V3

These early general conversational adapters explored a warmer, more natural voice. Short comparisons changed little on grounding and everyday replies; long support responses and default questions remained. The next step was to make Casper-specific behavior and system boundaries explicit.

What the comparisons did—and did not—show

Archived runs are named `qwen35-humanlike-qlora-pilot`, `qwen35-humanlike-qlora-v2`, and `qwen35-humanlike-qlora-v3`. Local V1/V3 comparisons were paired prompt examples, not a full multi-turn promotion gate. They suggested that surface style alone cannot guarantee concise replies, careful memory use, or reliable action results.

C4PUCA V4 · adapter and architecture

Casper V4 · conversation adapter, then clearer system boundaries

Early comparisons suggested a warmer, shorter reply to someone having a hard day and a more natural response to good news. They also made one thing clear: personal memories needed to stay grounded in Nix’s saved information, rather than the conversation model’s guesses. PUCA V4 developed that separation further. Its adapter is part of the project history.

C5Selectable fallback

Casper V5 · warmer conversational style

V5 gave Casper a warmer conversational style and is the non-beta local adapter listed in the source selector. Reviews also found moments where it asked a generic follow-up, leaned too hard into sympathy, repeated itself, explained too much, or lost track of a date. A warmer tone by itself didn’t solve those problems.

Runtime model ID

casper-puca-qlora-v5 · available only when local artifacts and the Transformers selector are present.

C6Beta · not promoted

Casper V6 · behavior-policy candidate

V6 explored how Casper handles follow-up questions, emotional context, and the difference between current and past information. In the latest recorded five-turn check, it handled 1 prompt as expected. That result shows there’s still room to improve across a conversation.

How the experiments evolved—and why V5 remains the fallback

Early versions scored 3/8 and 4/8 on an eight-prompt check. A later set of single-turn prompts scored 7/8; the same adapter scored 3/5 in an earlier multi-turn check and 1/5 in the latest one. The misses involved follow-up questions, asking too much, and keeping saved information straight while chatting. A good score on short prompts didn’t carry over to longer conversations.

Archived adapter experiments include `casper-puca-qlora-v6-sft`, `casper-puca-qlora-v6-targeted-sft`, `casper-puca-qlora-v6-policy-sft`, and `casper-puca-qlora-v6-final`. The selectable beta ID is casper-puca-qlora-v6; it is not the default.

Designed to run locally.

A compact model setup

Nix uses a smaller, quantized model representation to make local conversations practical.

02

Loaded when needed

The selected local model loads when you start a conversation with it. Nix keeps one companion model active at a time.

03

Conversation length is kept in check

Nix limits how much conversation history and how many new tokens the model handles at once. Luna’s recorded defaults are 24 history turns and up to 96 generated tokens.

04

Simple requests can be quick

Nix can recognize some common requests without waiting for the conversation model. In one small local timing check, these routing decisions took under 0.16 ms for Knowledge and 0.01 ms for social or general chat. That measures routing only, not the time for a full reply.

V5Current website/product label · September 2026

Nix PUCA V5

  • OpenAI-compatible API conversations now use isolated, namespaced thread IDs and do not inherit dashboard conversations.
  • The API Token Guard rejects structured OpenWebUI title, tag, and follow-up metadata-generation jobs before they reach Core or the conversation model—even without an embedded chat-history block.
  • Conversation browsing supports search and transcripts for dashboard and API-created chats.
  • Model selection keeps Official Luna as the local Transformers default, with Casper V5 and Casper V6 beta as separate choices when artifacts are available.
  • Skills marketplace supports app-style cards, public GitHub repository manifests, declared-file packages, install/uninstall status, and permission/source details. Community package code is not executed.
  • Dashboard page paths survive reloads, and the interface uses NIX PUCA's official light-only black-and-white theme.

Getting started

Point Open WebUI or any OpenAI SDK at the dashboard host. The endpoint runs the same Core pipeline as the dashboard: routing, Knowledge, Actions, and the configured official model's final response when the service runs.

Authentication

Set NIX_OPENAI_API_KEY to require a Bearer token. Leave it empty only on a trusted local network.

Chat completions

Send a user message to POST /v1/chat/completions. Use GET /v1/models to discover the model ID configured by this server.

curl "$NIX_BASE_URL/v1/chat/completions" \\ -H "Content-Type: application/json" \\ -H "Authorization: Bearer $NIX_OPENAI_API_KEY" \\ -d '{"model":"MODEL_ID_FROM_V1_MODELS","messages":[{"role":"user","content":"Hi"}]}'

Open WebUI

In Open WebUI, add an OpenAI connection using this dashboard URL plus /v1. Choose the model reported by that server. For the Transformers backend, Official Luna is the default; Casper can be selected separately. Non-Transformers backends bypass the local selector. This local status is not proof of hosted serving state. Only one local adapter is resident at a time. Both non-streaming and OpenAI SSE streaming are supported. When this source is served, streaming runs the configured Core → Knowledge → Actions → official-model flow, then progressively renders the answer.

Privacy and reset

Personal memory is stored by Nix Knowledge, not the UI. The Memories page exposes the rendered block, records, and a confirmation-protected reset that clears Knowledge, indexes, Actions, and sessions.
