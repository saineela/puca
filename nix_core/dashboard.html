Training data & evaluation

Contextual dialogue experiment

The archived training manifest reports 2,653 examples. Its exact component counts are 1,800 broad public-dialogue rows, 461 sampled project controls, 18 authored single-turn examples, 360 authored multi-turn trajectories, and 14 role controls. Of the broad rows, source counts are DailyDialog 1,292, No Robots 185, UltraFeedback chosen-SFT 183, and FineTome-100k 140. The 223 context-bearing examples are a subset of this total, not extra rows. The manifest says no personal logs were used.

Archived evaluator metadata records 18 held-out prompts and zero exact-normalized prompt overlaps in the built snapshot; it warns that semantic paraphrase overlap is not guaranteed. Reported matched checks for this adapter are 4/9 single-turn and 1/5 multi-turn in isolation, and 6/9 + 2/5 with evaluator-injected context. Injected-context results are not an end-to-end Nix Core/Knowledge/Actions test, and these are historical reports—not a new evaluation.

The adapter metadata points to luna_targeted_v6_contextual_v2_sft.jsonl. A later corrected V3 snapshot is separately documented as untrained and unscored; it did not produce these weights. Luna work remains V6 runtime/integration only: no new Luna training or evaluation is authorized.

Dataset citations, source links, and rights notes

  • DailyDialog: Li et al. (2017), ACL Anthology paper; the project source record lists CC BY-NC-SA 4.0.
  • No Robots: Hugging Face dataset card; project metadata records CC BY-NC 4.0.
  • UltraFeedback chosen subset: Cui et al. (2023), paper and dataset card; the project snapshot records MIT for its source, but the exact derivative/revision still needs verification.
  • FineTome-100k: dataset card; license/provenance is unresolved in archived notes. Treat it as uncleared.
  • Project-authored controls and role examples are not third-party datasets; see local source metadata luna_targeted_v6_contextual_v2_sft.metadata.json and the archived Luna V6 training metadata under nix_knowledge/models/.

Training data & evaluation

PUCA conversation style and policy

Casper V5’s metadata describes a style-only public-dialogue mix of 2,941 training and 400 evaluation rows (seed 42); it is not a factual or personal-memory corpus. Casper V6 records are separate snapshots: the initial SFT metadata reports 1,003 train / 250 eval rows, 53 curated rows, and six initial preference rows; later policy-conditioned records report 288 SFT rows and 144 internally approved preference pairs. These counts are not additive. The approved preference rows are project-reviewed data, not a third-party dataset citation.

V6 remains beta and is not promoted. Archived checks report 7/8 on a policy-conditioned single-turn set, 3/5 on an earlier direct multi-turn run, and 1/5 on the latest documented direct multi-turn check. These small checks do not establish release quality, current artifact availability, or hosted serving state.

The Luna research timeline

Every generation taught us something.

Scores come from archived, small diagnostic suites—not a claim about a live deployment or a quality guarantee.

L1–4Early base-model adapters

Luna QLoRA pilot · V2 · V3 · V4

The first Luna generations adapted Llama 3.2 3B Base using conversational-data mixes. They established the adapter workflow; they did not yet solve natural, reliable multi-turn conversation.

What changed between early versions

Archived run notes list the `luna-qlora-pilot` (12,600 examples, 60 steps), V2 (17,354 examples, 120 steps), V3 (10,716 examples, 160 steps), and V4 (12,015 examples, 400 steps). The clean-mix passes filtered boilerplate, repetition/confidence artifacts, injection text, and overlong turns. Ubuntu dialogue was dropped after adjacent, unrelated lines were found to break technical continuation. These local experiments were not selectable product releases.

I1Instruct baseline

Luna Instruct V1 · conversation baseline

Moving to an instruction-tuned Llama base gave the project a stronger matched comparison point. Paired probes later surfaced a key weakness: without trustworthy context, a model could invent personal details or claim an action had succeeded.

Identity, role, balanced, and baseline checks

The shared nine-case single-turn / five-case multi-turn harness reported Instruct V1 at 5/9 and 1/5. Identity V1 scored 2/9 + 0/5; Role V1 3/9 + 0/5; Balanced V5 checkpoint 80 scored 1/9 + 1/5. These scores are from the mixed Casper V6 contract, not Luna-identity-only scores. Failures included weak clarification, recurring-interval errors, unnecessary questions, and invented details. A separate paired fictional-context report gave the Instruct baseline 7/9 + 2/5; injected context was not an end-to-end Nix test.

V6Recovery and targeted runs

Earlier Luna experiments · recovery and curriculum

These historical V6 experiments focused on direct answers, identity boundaries, and multi-turn state. Some greetings and single-turn cases improved, but the gains did not carry consistently through a full conversation.

Archived checkpoints and test scores

On the same mixed Casper V6 contract, Luna Recovery V1 scored 5/9 and 4/9 single-turn, each 1/5 multi-turn. Targeted V2 scored 5/9 and 6/9 single-turn but did not sustain multi-turn performance in isolation; its higher context-assisted result (7/9 + 2/5) used evaluator-injected context. These small synthetic-context tests did not exercise the complete Nix stack. The archived curriculum and identity/role attempts are research history, not separate selectable releases.

OFFICIALOfficial · current source registry

Official Luna

This is the Luna adapter identified as official in Nix’s Transformers registry. Its stable runtime/API ID remains luna-v6-contextual-v1.

Test history and release-label context

The archived matched comparison reports 4/9 single-turn and 1/5 multi-turn in isolation, versus Luna Instruct V1’s 5/9 + 1/5. With evaluator-injected context, the figures were 6/9 + 2/5 versus 7/9 + 2/5. The old experiment metadata therefore recorded “not promoted” at that time: there was no matched score improvement. The current source registry separately designates Official Luna as official. That designation does not erase the old test results, constitute a new evaluation, or verify a hosted model.

A review also found an over-broad “sisters” hint in the historical training snapshot, which could invite an unrelated family question. A later corrected data snapshot is recorded as untrained and unscored; it is not what produced the current adapter weights.

PRORetired · not selectable

Luna Pro v1 · research candidate, not a release

The Pro pilot did not earn a release: review found made-up details, placeholder echoes, and missed clarifications; unresolved dataset provenance and rights also prevented distribution.

Specific reasons it stayed out of the lineup

In a frozen eight-case review, Pro missed the requested “which collaborator?” clarification. When asked to create a reminder, it said “I’m unable” rather than explaining that success needed an action result. A separate 144-row data review also flagged a fabricated day-trip destination for an unspecified city and placeholder echoes in constraint examples. The source materials recorded unresolved Topical-Chat and other dataset rights; there was no legal clearance to distribute it.

The current Nix source keeps Pro out of the selectable registry; its former endpoints return HTTP 410. The research is archive-only: do not reuse its data or training approach for any model. Luna work is restricted to the V6 runtime/integration path, with no new Luna training or evaluation authorized.

Casper’s model history

From warmer replies to grounded conversation.

Casper is the distinct, straight-to-work companion personality. Its adapter releases remain separate from Luna.

N1–3Early conversation adapters

Qwen3.5 humanlike · pilot, V2, V3

These early general conversational adapters explored a warmer, more natural voice. Short comparisons changed little on grounding and everyday replies; long support responses and default questions remained. The next step was to make Casper-specific behavior and system boundaries explicit.

What the comparisons did—and did not—show

Archived runs are named `qwen35-humanlike-qlora-pilot`, `qwen35-humanlike-qlora-v2`, and `qwen35-humanlike-qlora-v3`. Local V1/V3 comparisons were paired prompt examples, not a full multi-turn promotion gate. They suggested that surface style alone cannot guarantee concise replies, careful memory use, or reliable action results.

C4PUCA V4 · adapter and architecture

Casper V4 · conversation adapter, then clearer system boundaries

Early paired checks showed a warmer, shorter tired-user reply and a cleaner reaction to good news, while memory ownership still needed Core. PUCA V4 then separated dialogue/routing policy, Knowledge-owned personal facts and current states, and Actions-owned schedules. Its adapter was archived; V4 is not a current selectable model ID.

C5Selectable fallback

Casper V5 · warmer conversational style

V5 improved surface warmth and is Casper’s non-beta local adapter in the source selector. Request reviews also found generic follow-up questions, forced empathy, repeated acknowledgments, over-explaining, and answers that could lose dates. Style alone did not solve grounding or turn-taking.

Runtime model ID

casper-puca-qlora-v5 · available only when local artifacts and the Transformers selector are present.

C6Beta · not promoted

Casper V6 · behavior-policy candidate

V6 explored response acts, question budgets, emotional state, current-state precedence, and explicit grounding. It remains beta-only: the latest documented direct multi-turn check passed 1/5, with only state supersession passing.

How the experiments evolved—and why V5 remains the fallback

The early SFT/DPO and targeted adapters scored 3/8 and 4/8 on a direct eight-case check. A policy-conditioned single-turn set reached 7/8; its final adapter scored 7/8 single-turn and 3/5 in an earlier multi-turn run. A later direct five-turn run passed only state supersession (1/5), exposing unresolved clarification, question-discipline, and memory-plus-chat issues. A strong single-turn result was not enough to clear the multi-turn gate.

Archived adapter experiments include `casper-puca-qlora-v6-sft`, `casper-puca-qlora-v6-targeted-sft`, `casper-puca-qlora-v6-policy-sft`, and `casper-puca-qlora-v6-final`. The selectable beta ID is casper-puca-qlora-v6; it is not the default.

How Official Luna is structured inside Nix

A conversation model inside a system—not in place of one.

Luna is the voice for the final conversation. Core owns routing, Knowledge owns durable facts, and Actions owns scheduled work.

Models can phrase a reply; they do not write durable memory, schedule an action, or verify that an action succeeded. Core presents structured results so a fluent guess cannot substitute for a real record or confirmation.

How Nix improves

Better boundaries, not bigger promises.

Research and test gaps shaped Nix’s deterministic guardrails and Casper’s response-policy design. These are system-level improvements—not a claim that Official Luna was retrained or that retired Pro data or methods were reused.

♡

Memory stays grounded

Knowledge supplies recorded facts and current states. A conversational model is not the source of truth and should not invent a memory.

✓

Actions need results

Actions schedules work and reports its result. A model should never say a reminder was set when the system has not confirmed it.

↗

Ambiguity gets resolved

Deterministic routing, temporal parsing, and validation preserve dates and clarify uncertain people or requests before they become durable actions.

Under the hood

Small-footprint local inference.

Runtime details from source configuration; machine and hosted deployment state may differ.

01

Quantized adapter runtime

Transformers + PEFT with 4-bit NF4, double quantization, and bfloat16 compute for local inference.

02

Load only when needed

Weights are loaded lazily for a chat request. The exclusive GPU slot unloads the previous local companion before switching.

03

Bounded generation

KV caching is enabled; chat history and input length are bounded. The source defaults Luna to a 96-token generation ceiling and keeps its active conversation history to 24 turns.

04

Route before generation

Nix Core classifies supported routes without calling a neural routing model; selected fast paths can also answer without conversation-model generation. A documented 100-sample local benchmark measured route decisions in under 0.16 ms (Knowledge) and 0.01 ms (social/world chat); this is not a full-message or production-SLA claim.

  • OpenAI-compatible API conversations now use isolated, namespaced thread IDs and do not inherit dashboard conversations.

  • Model selection keeps Official Luna as the local Transformers default, with Casper V5 and Casper V6 beta as separate choices when artifacts are available.
  • Skills marketplace supports app-style cards, public GitHub repository manifests, declared-file packages, install/uninstall status, and permission/source details. Community package code is not executed.
  • Dashboard page paths survive reloads, and settings include persistent light/dark palettes plus selectable color themes.

Getting started

Point Open WebUI or any OpenAI SDK at the dashboard host. The endpoint runs the same Core pipeline as the dashboard: routing, Knowledge, Actions, and the configured official model's final response when the service runs.

Authentication

Set NIX_OPENAI_API_KEY to require a Bearer token. Leave it empty only on a trusted local network.

Chat completions

Send a user message to POST /v1/chat/completions. Use GET /v1/models to discover the model ID configured by this server.

curl "$NIX_BASE_URL/v1/chat/completions" \\ -H "Content-Type: application/json" \\ -H "Authorization: Bearer $NIX_OPENAI_API_KEY" \\ -d '{"model":"MODEL_ID_FROM_V1_MODELS","messages":[{"role":"user","content":"Hi"}]}'

Open WebUI

In Open WebUI, add an OpenAI connection using this dashboard URL plus /v1. Choose the model reported by that server. For the Transformers backend, Official Luna is the default; Casper can be selected separately. Non-Transformers backends bypass the local selector. This local status is not proof of hosted serving state. Only one local adapter is resident at a time. Both non-streaming and OpenAI SSE streaming are supported. When this source is served, streaming runs the configured Core → Knowledge → Actions → official-model flow, then progressively renders the answer.

Privacy and reset
